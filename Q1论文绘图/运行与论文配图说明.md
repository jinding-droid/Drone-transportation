来源：GitHub `jinding-droid/Drone-transportation` 的 main 分支，交付参考提交 `9b407179971ab49327fc2d23b70ac620ae1c0856`（2026-09-26）。本包附带该版本的五张 Q1 CSV 快照；实际运行输入的 SHA-256 写入输出目录的 `数据核对与来源.json`。未改动原始求解器和发布结果，未推送 GitHub。

## 运行

将本文件所在的 `Q1论文绘图` 文件夹放在任意位置，打开该文件夹的终端：

```powershell
python -m pip install numpy matplotlib
python .\代码\q1_figures.py
```

输出在 `结果/Q1论文图`：6组图，每组PNG（默认600 dpi）、PDF、SVG，共18个图文件。PNG适合Word；PDF适合LaTeX；SVG适合后续编辑。脚本不弹出图窗，直接保存文件。已附带本次运行生成的图片，可以直接使用。

如果要放回你们自己的仓库，仅将 `代码/q1_figures.py` 放到仓库 `代码` 目录，默认读取该仓库 `结果` 目录下的五张Q1表，不需要重跑优化。也可显式指定：

```powershell
python .\代码\q1_figures.py --results "F:\你的仓库\结果" --out "F:\你的仓库\结果\Q1论文图"
```

可选参数：`--dpi 300` 调低PNG分辨率；`--font "Microsoft YaHei"` 指定本机已安装的中文字体。Windows一般可直接运行，其他系统若缺中文字体请安装思源黑体（Noto Sans CJK SC）。运行依赖只有numpy和matplotlib；附带的原求解代码不需要执行。

## 图的用途与可用图注

| 图 | 建议位置 | 图注及解释口径 |
|---|---|---|
| 图1 最大安全载荷 | 单点往返能力分析 | 返航安全余量为20%时，三类无人机在各服务区的最大安全载荷。数值为质量与能量约束确定的载荷上限，不等于考虑箱体体积和不可拆分性后的实际装载量。 |
| 图2 机型方案比较 | 优化结果对比 | 统一采用A、B、C型与混合机型方案的架次数、总能耗和累计作业时间对比。各方案均完成全部服务区货物运输；混合方案按架次、能耗、累计时间的字典序求解，不称为无条件三目标同时最优。 |
| 图3 服务区机型分配 | 组批方案分析 | 混合机型方案的分服务区架次及机型构成。最终B型9架次、C型9架次，共18架次；S001、S002和S003各需2架次，其余服务区各1架次。 |
| 图4 利用率与SOC | 可行性及装载分析 | 各架次的安全载荷利用率和返航SOC。利用率=该架次实际质量/该机型对该服务区的最大安全载荷，区别于额定载重利用率与体积利用率；虚线分别为100%和最低返航SOC 20%。 |
| 图5 安全载荷敏感性 | 灵敏度分析 | S001、S004、S008、S015的最大安全载荷随安全余量变化。仅展示源表所含四个典型服务区；连线连接离散计算点，不代表重新求得连续函数。零载荷不能解释为可完成实际货物运输。 |
| 图6 全局方案敏感性 | 灵敏度分析 | 不同返航安全余量下混合机型方案的架次数、能耗与累计作业时间。在本表扫描范围内，0%至20%保持18架次；25%、30%、35%分别为19、20、25架次；40%不可行，不绘制为零。不能由离散扫描断言精确可行性临界点为40%。 |

正文篇幅有限时，优先图1、图2、图6；图3与图4可以择一放正文，另一放附录。图件自带标题，若论文采用正式图注，可在脚本中删去对应 `title` / `suptitle`，避免重复标题。

## 数据与结论边界

- 第一问累计作业时间是各架次作业时间之和，包含准备、装载、飞行、交接等源代码定义的环节；不是机队并行调度的最晚完工时间。源组批表列名虽为“往返时间s”，此处依求解代码语义称“累计作业时间”。
- 正式汇总：18架次、59.2403 kWh、32798.5 s（9.11 h），覆盖80箱、758 kg、2.011 m³。
- 逐架次CSV已舍入，其能耗相加为59.2401 kWh，与汇总59.2403 kWh相差0.0002 kWh。图2混合方案使用全局表汇总，校验允许逐行舍入误差；不修改任何源值以强行对齐。
- 脚本检查源表间一致性、货箱数量及去重、服务区覆盖、同区组批、安全载荷、SOC、总质量/体积及基准方案。该检查不是重新运行独立物理验证器，也不构成新的最优性证明。
- 源求解代码及共享记忆快照保留在包内供追溯；历史共享记忆中含已被替代的旧结论，论文数值以本次五张发布CSV和近期修订记录为准。
