# 协作者共享记忆

本文件用于记录协作者在本仓库中的实际工作内容、关键决定和交接信息。提交到 GitHub 时，除了在提交说明中概括本次修改，还必须同步更新本文件，确保后来加入的协作者能够快速了解项目进展。

## 使用规则

1. 开始工作前先执行 `git pull`，阅读本文件最近的记录，并确认自己负责的任务没有和他人重复。
2. 每完成一个明确任务，就在“工作记录”中新增一条记录。不要只写“已修改”“已更新”等无法复现工作内容的描述。
3. 每条记录至少写清：日期、协作者、任务、具体修改、涉及文件、验证方式、当前状态和后续事项。
4. 提交说明要和本文件中的记录对应。例如：`补充共享记忆协作规范`。提交说明用于快速浏览，本文件用于完整交接。
5. 不覆盖原始题目和原始数据。处理脚本、结果和中间文件应放在合适的独立目录，并在记录中说明输入、输出和用途。
6. 不记录密码、令牌、个人隐私或其他敏感信息；如需说明配置，只记录变量名、文件位置和脱敏后的示例。
7. 推送前检查 `git diff`、`git status` 和待提交文件，避免把无关文件、临时文件或大型未压缩文件上传到仓库。
8. 若发生冲突，先保留双方有效记录，再合并内容；不要删除他人的工作记录来解决冲突。

#### 一、总体主线

全题按「**一套物理内核 + 四层递进约束**」组织，避免四问各写一套模型：

```
物理内核（航段几何 + 能量 + 链路判定，全题复用）
   ├─ 第 1 层：去掉所有资源约束，只留单点往返       → 问题一
   ├─ 第 2 层：引入 8 架实体机 + 共享电池 + 时刻    → 问题二
   ├─ 第 3 层：再引入中继无人机与连续通信约束       → 问题三
   └─ 第 4 层：冻结问题三方案，只做资源归集切分     → 问题四
```

这样做的理由：
1. 题面 S59 要求「公共物理规则、单位、对象编号和计算口径保持一致」，单一内核天然满足；
2. 题面 S52 要求问题四「保持问题三安排不变」，所以问题四必须是问题三输出的**下游消费者**而非重新优化；
3. 读题报告已确认四问是层层加约束而非并列，主线必须能体现这一点。

#### 二、物理内核的三个模块与固化口径

| 模块 | 做什么 | 固化口径（及选择理由） |
|---|---|---|
| 航段几何 | 任意两节点间生成水平直线航段，输出水平距离、沿途最高高程、巡航海拔、爬升/下降高度 | ① 巡航海拔 = 航段**沿途** DEM 像元最高地面高程 + 50 m（用沿线而非两端点，题面 S63 明确要求）；② O01 作业高度 = 地面海拔，服务区 = 地面海拔 + 30 m（题面 S64）；③ 连续访问多服务区时每站投送后重新爬升，不是一次爬升到底 |
| 能量 | 给定载荷与航段，输出航段能耗 | ① 载荷修正**只走等效航程通道**：单位距离能耗 e(q) = E_use / L_g(q)，其中 L_g(q) 用题面给定的 3/2 次幂公式。理由：附录 2 只给了等效航程这一个与载荷相关的量，任何其他载荷修正都是自创；② 爬升附加能耗 = (空机质量 + 载荷) × g × 爬升高度 / 爬升效率；③ 下降效率取 0，不单独计下降能耗（题面明确） |
| 链路 | 给定三维端点对与时刻，判定链路可用性与通信状态 | 严格按附录 3 五步：地形遮挡（视线与 DEM 求交）→ 双向门限取较小值 → FSPL + 遮挡附加损耗 → 可用性布尔化 → 三态判定（直连 / 中继 / 中断）。不允许中继间多跳（题面 S83） |

关于能量口径的补充说明：单位距离能耗取 E_use / L_g(q)，其依据是「单组电池可用能量恰好覆盖等效航程」这一自然读法，即该机型以载荷 q 飞行时，用满全部可用能量能飞 L_g(q) 米。空载时退化为 E_use / L_g0，载荷增加时能耗单调上升，与物理直觉一致，已在自测中验证单调性。

#### 三、问题一的解题思路

**子问题 1：最大安全载荷。** 架次形态固定为 O01→Si→O01，所以这是一个**一维反解**问题：把「往返总能耗 ≤ (1−rho)·E_use」看作关于载荷 q 的不等式，q 越大能耗越高（单调），用二分法就能求出临界值，再与机型最大载货取小。设计上刻意没有引入优化，因为路径固定时没有自由度，二分是精确且最省算力的做法。

**子问题 2：货箱组批。** 关键观察：**全题 80 个货箱只有 4 种（质量, 体积）组合**——(3, 0.012) 医疗、(14, 0.027) 饮用水、(8, 0.028) 食品、(6, 0.035) 卫生。因此单服务区装箱不必按箱做 2^n 枚举（n=15 时那会超时，这是实际踩过的坑），而可以**按箱型计数做精确搜索**：一架次就是一个四元计数组合，可行组合数在几百量级，搜索空间从 32768 降到可忽略。这样既保证架次数最优，又能同时算出该方案的能耗。

**子问题 3：多目标权衡。** 三个指标（架次数、总能耗、累计作业时间）彼此不独立。设计上分两步做：① 先对每个服务区、每个机型算出三指标，形成「服务区 × 机型」对照表；② 再做归一化等权折中给出推荐机型。做这一步的原因是发现了一个**反直觉但在数据上很稳的规律**：小批量服务区用 C 型反而是浪费（大机小载，能耗与体积都不经济），大批量服务区用 C 型明显占优。这个规律后来直接作为问题二的机型选择先验。

**子问题 4：余量灵敏度。** 把 rho 从 0 扫到 0.40，同时输出最大安全载荷和该余量下的组批结果。设计时特意保留了「连最轻的箱子都装不下」这一边界情形，用不可行标记表示，因为这条边界恰好是给出机队配置建议的依据。

#### 四、问题二的解题思路（规划中，已定框架）

- **问题定位**：问题一 + 实体机数量 + 共享电池周转 + 充电时间 + 时限约束。相对问题一的核心增量是**时间维度**，而不是路径形态（问题一已把路径固定为单点往返，问题二才放开多点）。
- **主要难点**：如果按秒离散全场时间轴建混合整数规划，变量规模会爆。因此**不做全场时间离散化**，改用「事件驱动」的思路：只关心「架次开始 / 到达 / 投送完成 / 返回 / 充电完成」这些事件时刻，架次之间通过电池占用与充电完成时刻耦合。
- **求解框架**：两阶段分解。第一阶段做「箱组批 + 服务区访问顺序 + 机型指派」，用 LNS（大邻域搜索）在可行解空间里走；第二阶段做「电池与时刻的可行性分配」，本质是带释放时间的资源调度，可以用贪心 + 回溯精确校验。两阶段之间用「存在的可行时刻表」作为可行性证书，避免出现路线漂亮但电池排不开的假方案。
- **约束处理顺序**：先满足硬约束（时限、质量、体积、能量、电池互斥），再优化软目标。时限约束中，医疗物资与首批货箱是硬约束，其余物资的期望时间只进目标函数（题面 S34—S36 区分得很清楚）。
- **机型先验**：由问题一得出的「C 型适合大批量、B 型适合小批量」直接用于剪枝，减少 LNS 的无效邻域。
- **必做的可行性回检**：生成方案后必须重新逐架次核验质量、体积、能量、时限和电池时段互斥，并把回检脚本作为可运行程序的一部分交付（题面 S58 要求可运行程序，S39 要求检验资源可行性）。

#### 五、问题三的解题思路（规划中，已定框架）

- **问题定位**：问题二 + 连续通信约束 + 中继无人机决策。
- **中继位置的处理**：题面把悬停经纬度与飞行海拔都作为决策变量，但连续空间优化容易陷局部解且难复现。因此**主实现走离散候选点**：在 DEM 网格上按一定步长生成候选悬停位，用链路内核评估每个候选位对各架次各时段的覆盖效果；连续优化作为对照给出上界。离散粒度必须做敏感性分析，否则会被质疑「粗网格高估了中继需求」。
- **通信判定的时间处理**：不能只判巡航段。题面 S41 明确要求爬升、巡航、下降、物资投送四阶段连续通信。因此判定沿运输时间线逐段进行，在航段阶段切换点和投送点密集采样，段内利用几何连续性做外推。采样粒度也要做敏感性。
- **中继与直连的关系**：同一架次不同时刻可以分别用直连或中继（对应待澄清 T-07 的理解 A），否则地形遮挡严重区域会出现无解。中继服务时段必须覆盖被保障时刻，且一架运输机同时刻只能有一个保障源。
- **目标**：在问题二的四目标上再加「中继能耗」与「联合任务完成时间」，其中联合完成时间取两类无人机最后返航的最晚时刻。

#### 六、问题四的解题思路（规划中，已定框架）

- **核心设计决定**：问题四是**切分问题而非重优化问题**。题面 S52 明确要求保持问题三的组批、访问顺序、任务安排与通信保障关系不变，所以不能借分区之名重排路线。
- **分区生成**：以服务区为顶点、以「是否出现在同一架次」为边的强度构建关系图，用图划分得到 2 组与 3 组方案；同一架次涉及的服务区必须同组（题面 S53 的硬约束），这会在划分中体现为强制合并。
- **资源核算口径**：题面 S54 要求「各组独立执行所需资源」，所以资源需求是**组内峰值占用**，不是总量平均。这一点极易做错——按平均分摊会系统性低估需求，进而把资源缺口算小。
- **评价维度**：按题面 S55 给定的四个维度做比较——资源配置规模、资源冗余、组间工作量均衡、与现有库存的资源缺口。冗余与均衡都需要给出显式计算式（对应待澄清 T-09），不能只给形容词。
- **缺口分析**：与附件库存表逐机型核对，输出缺口量与原因。

#### 七、贯穿全题的几条设计原则

1. **口径可追溯**：任何数值都能指回附件字段或题面条款；不引入题目未给出的物理量。
2. **可复现优先于炫技**：所有含随机性的环节固定随机种子；宁可少用一个模型，也要保证结果能被第三方用同一套脚本复现。
3. **验证与求解分离**：每个模型都配一条独立验证路径（解析特例对照、下界比对、基线 gap、可行性重算），不用同一模型自证。
4. **假设显式声明**：待澄清清单 T-01—T-12 中的每一项都要在论文「模型假设」章节写清选择及其理由，不允许默默假设。
5. **边界情形不回避**：如「连最轻箱都装不下」「返航余量为 0」这类退化情形要显式处理并在论文中讨论，而不是让程序报错或悄悄跳过。

  2. 爬升附加能耗 = `(空机质量 + 载荷) × g × 爬升高度 / 爬升效率`，下降效率取 0 不单独计
  3. 巡航海拔 = 航段沿线 DEM 像元最高地面高程 + 50 m；O01 作业高度取地面海拔，服务区取地面海拔 + 30 m
- 关键结果：
  - 最大安全载荷（能量判据，kg）：A 型 12 个服务区可满载 25，S004=24.17、S008=21.71；B 型 S002=24.51、S003=23.84、S004=22.34、S008=20.96、S012=24.12，其余可满载 30；C 型 S002=50.62、S003=50.20、S004=45.65、S008=41.69、S012=50.10，其余 65–80
  - 单点往返（S001 满载）：A 飞行 982.5 s / 1.4628 kWh；B 880.4 s / 1.6160 kWh；C 919.4 s / 4.2175 kWh，均低于返航余量上限
  - 充电模型边界正确：s=0 → T_full；s=0.9 → 0.35×T_full；s=0.45 → 0.65×T_full
  - 等效航程端点与附件完全一致：L(0)=25000/28000/26000，L(Q)=20000/16000/12000
- 发现的数据现象：附件节点海拔与 DEM 采样存在最大 10.6 m 偏差（O01 差 1.0 m，S015 差 8.3 m）。原因是 DEM 为 30 m 网格的 DSM 且点位未做地形精化。处理方式：作业高度基准采用附件海拔（题面 S20 规定「以附件给定值为准」），DEM 仅用于计算沿线最高标高，两者口径需在论文假设中说明
