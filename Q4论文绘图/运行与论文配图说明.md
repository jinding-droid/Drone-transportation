# 第四问论文绘图

来源：https://github.com/jinding-droid/Drone-transportation 的main分支，参考提交 `9b407179971ab49327fc2d23b70ac620ae1c0856`，获取日期2026-09-26。采用Q4主结果及其冻结Q3快照 `Q4_from_Q3_d41ce99226be`。脚本先核对manifest记录的五张Q3表SHA256，不允许静默混用新Q3和旧Q4。

## 运行

解压后在本文件所在文件夹打开终端：

```powershell
python -m pip install numpy matplotlib
python .\代码\q4_figures.py
```

输出位于 `结果/Q4论文图`，6组图各含600dpi PNG、PDF、SVG，共18个图文件，已附带本次实际运行图片。Word可插入PNG，LaTeX可插入PDF。

若移回自己的仓库，复制 `代码/q4_figures.py` 和 `结果/Q4_绘图节点.json` 到对应目录，并确保结果目录中的两张Q4 CSV、Q4_input_manifest.json及五张Q3 CSV版本一致。也可指向包含全部这些输入的独立目录：

```powershell
python .\代码\q4_figures.py --results "F:\你的仓库\结果" --out "F:\你的仓库\结果\Q4论文图"
```

可选参数 `--nodes "节点快照.json"`、`--dpi 300`、`--font "Microsoft YaHei"`。无中文字体时请安装思源黑体（Noto Sans CJK SC）。若报告Q3输入哈希不一致，应取回Q4对应的冻结快照或重新求解Q4，不要删除哈希校验绕过错误。

## 推荐图注与使用位置

| 图 | 图注与口径 |
|---|---|
| 图1 两组/三组空间分区 | 服务区在两种方案下的任务归属，颜色与形状对应组号。坐标采用相对O01的局部距离近似，图中不绘制行政边界、连续覆盖区域或虚构区域多边形；不同K下相同组号不代表相同服务区集合。 |
| 图2 各组资源配置矩阵 | 各组独立执行任务所需的运输机、电池、中继机及中继能源组件数量。两图颜色范围统一，单元格给出实际数量。资源按源方案固定时序和峰值核算，不等于出现过的实体编号总数。 |
| 图3 资源需求与库存 | 两组/三组方案各类型总需求与现有库存对比。横杠表示该类型库存，柱高超过横杠即存在缺口。架和电池组是不同资源单位，不能直接折算成本。 |
| 图4 资源缺口与富余 | 正向柱为不足，负向柱为富余，按资源类型分别计算。负值仅为绘图方向，富余数量本身为正；不同类型不得相互抵消，总缺口不是需求总数减库存总数。 |
| 图5 工作量与任务均衡 | 上排为各组运输和中继任务累计占用时间，下排分别展示货箱数和运输架次数。CV按总体标准差除均值计算。工作量=运输任务时长+中继任务时长；不是并行完工时间，也不要求货箱数相等。 |
| 图6 独立分组的资源与能耗代价 | 未分区Q3、两组独立、三组独立执行的资源峰值配置合计与能耗对比。独立组需要各自复制完整中继任务窗口，从而增加中继资源与能耗。资源数量相加只是源模型的计数指标，不是经济成本。 |

正文优先图1、图3、图5；图4用于具体补充资源建议，图6用于解释独立分组的代价，图2可放附录。若正文另有正式图注，可删除脚本相应title/suptitle。

## 模型假设与验证边界

- 保持冻结Q3的运输架次、访问顺序和时间线，同一运输架次涉及的服务区必须同组。当前有11个不可拆分单元，其中两个非单站单元为{S002,S009}和{S003,S007,S011,S015}。
- 各组独立复制所需中继完整任务窗口，不跨组共享实体资源、不截短原窗口；组内同型资源允许重新编号。这是本次核算假设，不声称是题意唯一解释。
- 工作量CV阈值10%来自建模设定，不是题面硬性给定条件。结论适用于当前冻结任务、阈值、资源核算及字典序目标，不证明所有可能Q3/Q4联合方案最优。
- 本次绘图校验：五张Q3冻结输入哈希、15服务区唯一覆盖、不可拆单元、22运输架次唯一继承、按保障关系复制的中继架次、各组货箱/能耗/时长、工作量与CV、资源总配置/逐类缺口/富余及货箱极差。
- 本次未重新计算含电池充电的峰值资源配置，也未重新枚举分区优化；图中资源数量读取已发布Q4结果。源代码独立验证应继续使用原q4_validate.py。
- 图件来源哈希与核对结果保存在 `数据核对与来源.json`。节点快照来自原始附件，与前三问使用同一坐标口径。
